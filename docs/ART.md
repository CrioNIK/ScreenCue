# Visual assets

The ScreenCue mark and selected SKETCH arrow were generated with the built-in OpenAI image generation tool for this project. No external brand artwork is included. The mark's PNG and ICO are source/documentation assets; the Rust executable loads neither. The on-screen arrow uses an embedded raster sprite atlas. Target outlines and compact labels are drawn in code, without a branded header.

The user selected the fourth concept, SKETCH: overlapping rough red pencil/marker strokes, a scribbled triangular head, and transparent gaps between strokes. The image tool then edited that reference into four neighboring drawings on a transparent 2 × 2 sprite sheet. The generation instructions are preserved in [SKETCH-PROMPT.md](SKETCH-PROMPT.md). The production atlas, [assets/sketch-atlas.png](../assets/sketch-atlas.png), is 512 × 348 pixels, containing four 256 × 174 RGBA frames. It is embedded in the executable and decoded once when the first arrow is rendered; the four decoded frames occupy 712,704 bytes (about 0.68 MiB), before other rendering buffers.

Playback holds the drawings in the sequence `0,1,2,3,2,1` at 5 steps per second, a 1.2-second loop. The renderer anchors the tip, aligns the tail-to-tip axis, and clips stray generated flecks beyond the tip guard. Tinting preserves the source alpha texture and only updates when the chosen color changes. This is a sequence of held drawings, not a continuously morphed vector curve.

The arrow and empty target contour are independent drawable objects. The target can be an ellipse, rectangle, rounded rectangle, or polygon; it has no fill. The arrow ends before the target edge with a 12 px gap (scaled for display density). The light contour updates at about 12 fps. Animation at a stationary target keeps the tip, label and native window fixed; following a moving application translates the cue. `animate: false` freezes the drawings while still allowing window tracking. The default arrow scale is 1.6; fitting near a display edge can uniformly shorten the arrow while preserving the tip anchor and separation. The target stroke stays at 1.3 px.

Red is the primary color. Automatic color keeps red where it has enough contrast, changes to a clearer candidate when red blends into the background, and returns to red when suitable. It scores luminance contrast and local color similarity using alternating transient 64 × 64 patches at the target and shaft, about one patch per second while visible. The two recent patches are combined. Own ink pixels are excluded, deterministic stratified samples avoid fixed-stride texture aliasing, and hysteresis limits color chatter. It does not save, transmit, or provide pixels as screenshots. An explicit `#RRGGBB` color or agent-provided background palette bypasses sampling. A single color cannot guarantee contrast against every pixel of arbitrary moving backgrounds; the algorithm reports capture failures.

Project-mark prompt:

> Use case: logo-brand. Asset type: small app identity sticker for ScreenCue, a tiny desktop screen hint utility for a punk user. Create one compact emblem, square composition, true transparent background. A bold angular upward arrow with a slightly hand-cut silhouette points toward an empty ring but STOPS SHORT of the ring with a clear gap; the ring interior stays empty. Punk zine / DIY screenprint attitude, subtle rough ink edges but very simple broad shapes legible at tiny icon sizes. High contrast acid yellow and warm off-white strokes with a small hot-pink offset accent, restrained charcoal outline. No words, letters, numbers, slogans, mockup surfaces, gradients, shadows, or extra symbols. Emblem fills most of the square with modest transparent padding. Crisp graphic raster artwork, not a photo.

`preview.png` and `preview.gif` show deterministic output from the actual Rust renderer on a neutral background, not a capture of a user's desktop. Reproduce a frame with `screencue --render-preview docs/preview.png 0`; the last argument is animation time in seconds. Preview generation uses an explicit color and does not read desktop pixels. Local capture on macOS needs macOS 15.2+ and previously granted screen-recording permission; otherwise a supplied palette or a reported fallback is used.
